Every instance in this system is named `kind:id`, and the kind comes from the closed set below. There is no registration hook: a new kind is a change to the descriptor table in Go and to this page in the same commit.

The set has two halves. A **configurable** kind is declared in the configuration document and created, edited and deleted through `/api/v1/resources`. An **intrinsic** kind names something the system already knows, so no operator declares one: a printer arrives when a connector admits it, and a node arrives when a link handshake completes. Both halves are addressable, because the event envelope, the health key and the authorization key are one vocabulary and a second set here would drift from it.

An id is a DNS-1123 label: lowercase letters, digits and `-`, starting and ending with a letter or a digit, at most 63 bytes. That intersection is what makes one string legal at once as a URL path segment, a metric label, a config key and a messaging subject token.

## Vocabulary version

This build carries `resource-kinds` version `1.6.0`, in format `1.1`. The content version moves when a kind is added, retired or redefined; the format version moves when the shape of an entry changes, so a consumer can tell a reshaped artefact from a reworded one.

## The set

Each kind below is its own section, anchored by the kind name.

### `storage` {#storage}

Where uploaded files and job artefacts are kept.

- **declared in configuration** yes
- **runtimes** `builtin`, `service`

A storage instance is a place bytes live: a directory on the host, a bucket, or a temporary area that is emptied on restart. Uploads, job files and camera snapshots are addressed through one, and an instance that is not ready takes only the feature that needs it out of service.

### `auth` {#auth}

An identity provider that turns a credential into a principal.

- **declared in configuration** yes
- **runtimes** `builtin`, `service`

An auth instance runs the login ceremony and resolves the caller of a request into the subject the authorization graph is keyed by. It decides who somebody is and never what they may do, which is the authorization graph's answer and not this one's.

### `sink` {#sink}

An outbound destination events are delivered to.

- **declared in configuration** yes
- **runtimes** `builtin`, `service`, `script`

A sink instance forwards the event stream somewhere off this process: a broker, a queue or an HTTP endpoint. It attaches downstream of the state update, so a slow or failing sink never delays a printer frame reaching a browser.

### `driver` {#driver}

A printer connector: the code that speaks one device protocol.

- **declared in configuration** yes
- **runtimes** `builtin`, `service`

A driver instance is a configured connector, and the capability keys it declares are what the API offers for the printers it serves. Printers themselves are not declared here: a device dials in and is admitted by the connector that answers it.

### `db` {#db}

A record backend: the key/value store a module's namespace is served out of.

- **declared in configuration** yes
- **runtimes** `builtin`

A db instance is the store behind sdk/stateapi. A module is handed a namespace of its own out of it and cannot tell one backend from another, which is why the contract is unchanged whichever instance serves it. It holds no event history: that is the history kind, whose contract shares no method with this one. SQLite and Postgres are both first class, and an instance owns its own store, its own credentials and its own migration ledger.

### `camera` {#camera}

A source of still images or a video stream for a printer.

- **declared in configuration** yes
- **runtimes** none, because no instance of this kind is declared

A camera is a device beside the printers, added through PUT /api/v1/cameras/{camera} and kept in the server's database, so a snapshot is authorized, streamed and audited through the same path as telemetry. No configuration file declares one.

### `history` {#history}

A store that keeps metrics and events after the hub has forgotten them.

- **declared in configuration** yes
- **runtimes** `builtin`

A history instance subscribes to the event bus under a principal of its own and stores what it is granted: telemetry as samples against the state path it was reported under, state and audit events whole. It declares what it keeps and for how long, and a query it cannot answer truthfully is refused rather than approximated. A deployment that declares none has no past, and every feature that needs one is absent and says so.

### `link` {#link}

This site's link to one parent site.

- **declared in configuration** yes
- **runtimes** `builtin`, `service`

A link instance carries this site's device state up to one parent and the parent's commands down, and nothing else: a print file travels by URL and the device fetches it. A deployment declares at most one, because a node has one parent. A parent commands a child as an ordinary principal, so what it may do on this site is a grant written here and never a property of the wire.

### `asset` {#asset}

A module that ships files for the browser and runs no process.

- **declared in configuration** yes
- **runtimes** `asset`

An asset instance is a directory of files and the digest recorded over them, installed the way a module is and declared under the module's type. The host verifies the digest at every start and serves the files at /api/v1/modules/&lt;namespace>/ui/, authorizing each request on the instance the way it authorizes a module's own routes. Nothing is launched: a page loads the entry file as a script, and the instance is enabled and disabled like any other.

### `gcode-preset` {#gcode-preset}

A named, stored gcode sequence a caller runs against a printer.

- **declared in configuration** yes
- **runtimes** none, because no instance of this kind is declared

A preset is a maintenance macro: an ordered list of gcode commands, the models it was written for, and a name. It is configuration rather than something that runs, so nothing supervises one. Writing a preset takes configure_resource on this kind and reading one takes view_resource; running one takes send_gcode on the printer and nothing on this kind at all, so an operator may be trusted with a macro they may not rewrite.

### `dashboard` {#dashboard}

A page of cards a person lays out, drawn on the home page.

- **declared in configuration** yes
- **runtimes** none, because no instance of this kind is declared

A dashboard is a grid of cards: printers, the fleet, temperatures, cameras, notes. It is configuration rather than something that runs, so nothing supervises one. Each dashboard says who sees it: reading one at the level everyone takes view_resource on this kind, at the level operators takes operate_resource, and at the level administrators takes configure_resource. Making, changing or deleting one takes operate_resource, and choosing the default one takes configure_resource.

### `printer` {#printer}

One physical printer, registered by the device plane.

- **declared in configuration** no
- **runtimes** none, because no instance of this kind is declared

A printer is intrinsic: it is not declared in the configuration document and has no resource API. It arrives when a connector admits a device, carries a fleet-unique identity, and is addressable here because the event envelope, the health key and the authorization key are one vocabulary.

### `node` {#node}

A peer site this server is linked to.

- **declared in configuration** no
- **runtimes** none, because no instance of this kind is declared

A node is another installation of this product, federated with this one. It is intrinsic for the same reason a printer is: the link handshake creates it, no configuration block declares it, and events forwarded from it keep the source the origin wrote.

## Runtimes

An instance declares one of these under `runtime`. It says what is behind the instance, which is a different question from whether the instance runs. A kind refuses a runtime it does not offer at load, and the refusal names what it does offer.

### `builtin` {#builtin}

A type compiled into this binary.

The implementation ships in this artefact and is resolved through the type registry by the name written under type. It is the default, and it is the only runtime an instance created through the resource API can have.

### `service` {#service}

A type reached as a supervised child process.

The implementation is a separate binary the host launches and speaks to over a socket. The instance declares where that binary is, the digest that proves it is the one installed, and the wire major it implements, and a mismatch on any of the three is a refusal rather than a warning.

### `script` {#script}

An expression the operator wrote, compiled by the host.

There is no implementation to reach: the script is the implementation. It is handed one event and returns the messages the host publishes, so it transforms and routes and never performs the effect itself. Only a sink offers it, because a script has no assignment, no loop and no way to remember anything between events.

### `asset` {#asset}

A directory of files the host serves and never runs.

The instance declares where the directory is and the digest recorded over every file in it. The host checks the digest at every start and serves the files under the module's namespace; nothing is launched, and a directory that no longer matches its digest is refused rather than served. Only the asset kind offers it.

## Reading the set from a running server

`GET /api/v1/vocabularies/resource-kinds` answers with what **this build** carries, from the same table this page is generated from. A page describes the release it was generated from; the endpoint describes the binary that is running.
