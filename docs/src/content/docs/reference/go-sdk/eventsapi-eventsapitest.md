`eventsapitest` is the conformance suite an event sink passes. Every clause
of `Processor` is a property of what happens when the destination stops
answering, so the suite points the sink at `BlackHole`. That is a listener
that accepts every connection and answers nothing. A wedged broker, a paused
container and a black-holed route all look like that from the client side.
`RunProcessorContract` then proves that no method blocks, no method panics,
and `Close` leaves no goroutine behind.

Make the destination once, outside the factory, for the reason the camera
suite gives: one subtest counts goroutines across a build and a `Close`.

```go
package acmehook

import (
	"testing"

	"github.com/prusa3d/prusa-connect/sdk/eventsapi"
	"github.com/prusa3d/prusa-connect/sdk/eventsapi/eventsapitest"
)

func TestContract(t *testing.T) {
	// A destination that accepts every connection and answers nothing, which
	// is what a wedged broker looks like from the sink's side.
	address := eventsapitest.BlackHole(t)

	eventsapitest.RunProcessorContract(t, func(*testing.T) eventsapi.Processor {
		return newSink("http://" + address + "/events")
	})
}
```

## `eventsapi/eventsapitest` {#eventsapi-eventsapitest}

```go
import "github.com/prusa3d/prusa-connect/sdk/eventsapi/eventsapitest"
```

Package eventsapitest provides the conformance suite every eventsapi.Processor must pass, so a sink written by a community author behaves the way the event bus needs it to and the built-in ones do not get to be special.

The contract eventsapi.Processor states is short and every clause of it is a property of what happens when the destination stops answering: the caller is the event bus, so a method that blocks stalls every other subscriber, and a sink that panics takes the process with it. The suite therefore runs a processor whose destination accepts connections and never answers, which is the state a broker under load, a paused container and a black-holed route all present, and asserts the contract holds there.

Usage from a sink's \_test.go:

	func TestContract(t *testing.T) {
	    address := eventsapitest.BlackHole(t)
	    eventsapitest.RunProcessorContract(t, func(t *testing.T) eventsapi.Processor {
	        p, err := New(eventsapi.ProviderSpec{Type: Type, Config: map[string]any{
	            "url": "tcp://" + address,
	        }})
	        if err != nil { t.Fatal(err) }
	        return p
	    })
	}

The destination is made once, outside newProcessor, because one subtest compares the live goroutines across a build and a Close and a fixture started inside newProcessor would be read as the sink's own.

### `BlackHole` {#eventsapi-eventsapitest-blackhole}

```go
func BlackHole(t *testing.T) string
```

BlackHole starts a listener that accepts every connection and answers nothing, and returns its host:port. It is what a sink's destination is pointed at for the suite: a refused connection fails fast and proves little, while a connection that is accepted and then silent is what a wedged broker looks like from the client side.

Accepted connections are held open until the test ends, and nothing is spawned per connection, so the goroutine count a subtest reads does not move when a sink dials.

### `RunProcessorContract` {#eventsapi-eventsapitest-runprocessorcontract}

```go
func RunProcessorContract(t *testing.T, newProcessor MakeProcessor)
```

RunProcessorContract runs the conformance suite against the processor produced by newProcessor. Each subtest gets its own instance.

### `MakeProcessor` {#eventsapi-eventsapitest-makeprocessor}

```go
type MakeProcessor func(t *testing.T) eventsapi.Processor
```

MakeProcessor builds a fresh Processor for one subtest, pointed at a destination that accepts connections and never answers.
