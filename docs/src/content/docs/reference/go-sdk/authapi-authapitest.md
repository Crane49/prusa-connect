`authapitest` is the conformance suite an identity provider passes before it
ships. A test calls `RunIdentityProviderContract` with a function that builds
a fresh `Harness` for each subtest: the provider, and the inputs that make one
login succeed for each flow it advertises.

A credentials provider names `ValidUsername` and `ValidPassword`. A redirect
provider sets `Callback`, which plays the browser's part against the
authorize URL `BeginLogin` produced. A nonce or a PKCE challenge minted in
that call is then answered rather than replayed. A bearer provider sets
`ValidToken`, and `SignRS256` mints one for a test issuer. The suite proves
that every advertised flow yields an identity, that an unadvertised flow
answers `ErrUnsupportedFlow`, and that a redirect provider refuses the answer
to another login.

```go
package acmesso

import (
	"context"
	"testing"

	"github.com/prusa3d/prusa-connect/sdk/authapi/authapitest"
)

// table is a directory holding one account, which is all the suite needs to
// drive a successful login.
type table map[string]string

func (t table) Bind(_ context.Context, username, password string) ([]string, bool) {
	if t[username] != password {
		return nil, false
	}

	return []string{"viewer"}, true
}

func TestContract(t *testing.T) {
	authapitest.RunIdentityProviderContract(t, func(t *testing.T) authapitest.Harness {
		return authapitest.Harness{
			Provider:      &provider{directory: table{"ana": "correct horse battery"}},
			ValidUsername: "ana",
			ValidPassword: "correct horse battery",
		}
	})
}
```

### `SignRS256` {#authapi-authapitest-signrs256}

```go
func SignRS256(key *rsa.PrivateKey, header, claims map[string]any) string
```

SignRS256 renders header and claims as a compact JWS under key, for a test issuer. The header is the caller's, which is how a token claiming an algorithm nobody should accept is produced: the signature is always RS256 whatever the header says, and a verifier that reads the header first refuses it before checking.

### `Harness` {#authapi-authapitest-harness}

```go
type Harness struct {
    Provider authapi.IdentityProvider
    // ValidUsername / ValidPassword are required when the provider advertises
    // Capabilities.Credentials.
    ValidUsername string
    ValidPassword string
    // ValidCallbackParams, for a Redirect provider, are callback parameters that
    // make CompleteLogin succeed (e.g. url.Values{"code": {"..."}} for OIDC, or
    // {"SAMLResponse": {"..."}} for SAML). When set, the suite drives a full
    // begin→complete happy path and (for revalidating providers) re-checks the
    // resulting subject.
    //
    // A provider that binds one login to values it generated inside BeginLogin,
    // which every OIDC and SAML provider does, cannot be driven from a fixed
    // set. Those set Callback instead.
    ValidCallbackParams url.Values
    // Callback drives the identity provider the way a browser would: it takes
    // the authorize URL BeginLogin just produced, and returns the parameters the
    // provider would send back to the callback for it.
    //
    // It is what a redirect provider that is doing its job needs. A nonce and a
    // PKCE challenge are made inside BeginLogin and travel in the authorize
    // request, so the answer to one login is not the answer to another, and a
    // fixed set of parameters can only be minted by an issuer that ignores both.
    //
    // When set, the suite drives the whole redirect flow through it, and holds
    // the provider to refusing the answer to a different login.
    Callback func(t *testing.T, authorizeURL string) url.Values
    // ValidToken, for a Bearer provider, mints a token the provider's issuer
    // signed and the provider accepts. When set, the suite holds the provider
    // to yielding a subject and an expiry for it.
    ValidToken func(t *testing.T) string
}
```

Harness describes a provider under test plus the inputs the suite needs to drive a successful authentication for whatever flow(s) the provider supports.
