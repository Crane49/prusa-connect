`fractal` is the Prusa Fractal protocol written as Go types: node paths, the
messages, error codes, request ids and the patterns that select interfaces. It parses and checks them. Every other Fractal package in this SDK
imports it.

## Prusa Fractal in this SDK {#prusa-fractal}

Prusa Fractal is a protocol for a tree of sites. Another team at Prusa
specifies it, and the specification is not part of this repository. A node has
at most one node above it and any number below it, and it talks only to those.
A node is named by its path from the root, such as `hq/brno/printer-1`.

Each node owns interfaces. An interface is a named set of properties and
methods, such as `FDMPrinter1` on a printer. A node reports the state of its
interfaces upward. It accepts method calls and property change requests from
the nodes above it. A node can keep a copy of the state of the nodes below it,
and the protocol calls that copy the shadow.

| message | direction | what it says |
|---|---|---|
| `REP` | up | these properties of my interface have these values |
| `DES` | down | please change these properties |
| `RPC` | down | run this method |
| `RES` | up | the result of that method, or an error code |
| `LOS` | up | the connection to a node below me is gone |
| `RBR` | down | report your full state again |

This SDK implements the specification with the Go standard library alone:

- [`node`](./fractal-node.md) is the engine. One `Node` is one node of the
  tree. It routes messages, runs method calls and lets the application call
  the nodes below. A transport plugs into it through a small contract,
  `node.Binding`
- [`shadow`](./fractal-shadow.md) stores the copy of the state of the nodes
  below
- [`join`](./fractal-join.md) has the rules by which a server asks to join
  under another server, and by which that server decides
- [`schema`](./fractal-schema.md) describes an interface as a JSON file and
  checks messages against it
- [`prusa`](./fractal-prusa.md) has the Prusa printer interfaces as such files
- [`fractaltest`](./fractal-fractaltest.md) has a transport that works in
  memory, and the conformance suite that every transport must pass

The transport over NATS is not in the SDK. It is in the module under
`packages/fractal` of this repository.

## When to import this package directly

An application that wants a working node starts at [`node`](./fractal-node.md),
and `examples/fractal-tree` is a complete program with three nodes in one
process. Import `fractal` on its own to write a transport, or a tool that
reads Fractal messages. A message is a plain struct with JSON tags: decode it
with `encoding/json`, then call `Validate`.

```go
package relay

import (
	"encoding/json"
	"fmt"

	"github.com/prusa3d/prusa-connect/sdk/fractal"
)

// self is the path of the node this code runs on.
const self = fractal.NodePath("hq/brno")

// readReport decodes a state report that arrived from below and checks it.
func readReport(payload []byte) (fractal.REP, error) {
	var report fractal.REP
	if err := json.Unmarshal(payload, &report); err != nil {
		return fractal.REP{}, err
	}

	// Validate checks the version, the sender path and every name.
	if err := report.Validate(); err != nil {
		return fractal.REP{}, err
	}

	// A report is only accepted from this node's own subtree.
	if !self.IsAncestorOf(report.Sender) {
		return fractal.REP{}, fmt.Errorf("%s is not below %s", report.Sender, self)
	}

	return report, nil
}

// nextHop answers which node directly below this one a method call goes to.
func nextHop(call fractal.RPC) (fractal.NodeID, error) {
	child, ok := self.NextHop(call.Receiver)
	if !ok {
		return "", &fractal.Error{Code: fractal.CodeNodeNotFound, Message: "no such node below " + self.String()}
	}

	return child, nil
}
```

This package does no input and no output. It starts no goroutine and reads no
clock. A property value, a method parameter and a method result stay as
`json.RawMessage`, and this package does not check their types:
[`schema`](./fractal-schema.md) does.

## `fractal` {#fractal}


Package fractal defines the Go types of the Fractal protocol: names, node paths, messages, error codes, RPC ids and shadow selection patterns.

Fractal arranges devices as trees of nodes. A node exchanges messages only with the one node above it and the nodes below it. Upward it reports state with REP and a lost node with LOS. Downward it sets properties with DES, calls a method with RPC (answered with RES) and asks for a full report with RBR. AREP, ALOS and ARBR are the same in the other direction. The copy a node keeps of the state of other nodes is the shadow.

This package does no input or output, starts no goroutine and reads no clock. Where it disagrees with the Fractal specification, the specification is right.

### `Code` {#fractal-code}

```go
type Code uint16
```

Code is the error code of a failed RPC and of a denied join request.

Bit 15 is set in a code an application or a transport binding defines. Bit 14 is set when the caller caused the failure. Bit 13 is set when the callee decided to refuse. Bits 12 to 9 are reserved and must be zero. Bits 8 to 4 number the code. Bits 3 to 0 are a refinement, and zero is the base form.
