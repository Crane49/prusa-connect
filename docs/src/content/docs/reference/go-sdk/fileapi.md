`fileapi` is how the core asks a module about one file. A module imports it
when its manifest names file types under `file_analysis`. The core then asks
it for the picture, the details and what a printer needs of such a file.

The core calls `file.analyze` with a read handle for one file. `Serve` opens
the file through the handle with `storageapi.Client.Open` and hands it to the
module's function, which answers an `Analysis`. The answer is held to the
bounds this package publishes before it leaves the module. The core keeps its
own reader for a module that fails or is slow.

```go
methods := wirerpc.Methods{
    fileapi.MethodAnalyze: fileapi.Serve(storageapi.NewClient(conn), analyze),
}

func analyze(ctx context.Context, params fileapi.Params, file *storageapi.File) (fileapi.Analysis, error) {
    head := make([]byte, min(file.Size(), 4096))
    if _, err := file.ReadAt(head, 0); err != nil && !errors.Is(err, io.EOF) {
        return fileapi.Analysis{}, err
    }

    return fileapi.Analysis{Title: firstLine(head)}, nil
}
```

## `fileapi` {#fileapi}

```go
import "github.com/prusa3d/prusa-connect/sdk/fileapi"
```

Package fileapi is how the core asks a module about one file.

A module names the file types it reads under file\_analysis in its manifest. When the core needs such a file described, it calls MethodAnalyze on that module with a read handle for that one file. The module reads the file with storageapi.Client.Open, which needs no read\_storage permission, and answers an Analysis.

When the module is not serving, fails, answers out of bounds or takes too long, the core reads the file itself.
