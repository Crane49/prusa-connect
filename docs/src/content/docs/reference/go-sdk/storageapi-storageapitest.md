`storageapitest` is the conformance suite a storage provider passes.
`RunProviderContract` reads `Probe`, not `Capabilities`, so the shape it runs
is the shape the compiler already agreed to. That is the browse and write
halves the provider declares, plus each optional interface it implements.

A `Subject` declaring `Browse` and `Write` sets either `Root`, the directory
the objects live in, or `NoFilesystemRoot`. Never both and never neither.
`Root` is what lets the suite plant a symlink or a junction inside the store
and require every operation to refuse it. An omission that quietly skipped
those cases would let a provider certify with no confinement at all.
`RunStreaming` is a second entry point. It moves a 512 MiB object through
`Save` and back out through `Open` inside a process whose heap is bounded. A
provider that buffers the object fails there rather than on a Pi.

```go
package acmes3

import (
	"testing"

	"github.com/prusa3d/prusa-connect/sdk/storageapi"
	"github.com/prusa3d/prusa-connect/sdk/storageapi/storageapitest"
)

func TestContract(t *testing.T) {
	storageapitest.RunProviderContract(t, func(t *testing.T) storageapitest.Subject {
		bucket, err := openBucket("acme-test/" + t.Name())
		if err != nil {
			t.Fatal(err)
		}

		return storageapitest.Subject{
			Provider: &store{id: "s3", name: "S3", bucket: bucket, allowed: storageapi.DefaultAllowedExtensions},
			// The objects live in a bucket, so the suite has nowhere to plant a
			// link and skips the escape cases. Declaring that is required.
			NoFilesystemRoot: true,
		}
	})
}
```

## `storageapi/storageapitest` {#storageapi-storageapitest}

```go
import "github.com/prusa3d/prusa-connect/sdk/storageapi/storageapitest"
```

Package storageapitest provides a reusable conformance ("contract") test suite for storageapi.Provider implementations, so every provider behaves consistently against the contract.

The suite reads storageapi.Probe, not Capabilities. A provider declares only whether its browse half and its write half return real data; the four optional abilities come from the interfaces it implements, so the shape the suite runs is the shape the compiler already agreed to.

Usage from a provider's \_test.go:

	func TestContract(t *testing.T) {
	    storageapitest.RunProviderContract(t, func(t *testing.T) storageapitest.Subject {
	        p, err := storageapi.BuildProvider(storageapi.ProviderSpec{ID: "x", Type: "..."})
	        if err != nil { t.Fatal(err) }
	        return storageapitest.Subject{Provider: p}
	    })
	}

RunStreaming is a second entry point, run separately:

	func TestNothingScalesWithFileSize(t *testing.T) {
	    storageapitest.RunStreaming(t, ...)
	}

It proves that nothing on the provider's path holds a share of the object. It is not folded into RunProviderContract because it moves half a gigabyte through the provider twice and forks a process to bound the heap while it does, which is not a cost every run of the contract should carry.

### What a subject has to declare

A provider declaring Browse and Write is returned fresh and empty, with the default upload allowlist, so the extension check runs.

Such a provider sets either Subject.Root, the directory it keeps its objects in, or Subject.NoFilesystemRoot. Never both and never neither. Root is what lets the suite plant a link inside the store and prove it opens no way out.

A storageapi.Presigner sets Subject.ResolvablePath, the one path the suite requires it to turn into a URL.

A storageapi.LocalFiles also declares Write, because the suite writes a file before opening a handle to it, and sets Subject.Root.

### `TransferSize` {#storageapi-storageapitest-transfersize}

```go
const TransferSize int64 = 512 << 20
```

TransferSize is how large the object a provider is streamed is: 512 MiB.

The number is chosen against the deployment this product is sized for. Earlier research sets GOMEMLIMIT to 384 MiB on a 1 GB Pi, so an object this size cannot be held in the heap at all: a provider that buffers it is asking the kernel to kill the server, not asking the garbage collector to work harder.

### `RunProviderContract` {#storageapi-storageapitest-runprovidercontract}

```go
func RunProviderContract(t *testing.T, newSubject MakeSubject)
```

RunProviderContract runs the conformance suite against the provider produced by newSubject, asserting the surface it declares and the abilities it implements. Each subtest gets its own provider instance.

### `RunStreaming` {#storageapi-storageapitest-runstreaming}

```go
func RunStreaming(t *testing.T, newSubject MakeSubject)
```

RunStreaming proves that a provider moves an object without holding it, which is an earlier design decision and the property earlier research states as "nothing else should scale with file size".

It streams an object larger than the heap a Pi-sized deployment is given through Save and back out through Open, inside a second process whose live heap is bounded. The second process is the point: a machine with plenty of memory streams a large file just as happily whether or not the provider buffers it, so the case has to be run somewhere the buffering is fatal.

Call it from a provider's own test:

	func TestNothingScalesWithFileSize(t *testing.T) {
	    storageapitest.RunStreaming(t, func(t *testing.T) storageapitest.Subject {
	        return storageapitest.Subject{Provider: ..., Root: dir}
	    })
	}

The subject is built again inside the second process, so the factory must not depend on anything the parent set up.

### `Subject` {#storageapi-storageapitest-subject}

```go
type Subject struct {
    Provider storageapi.Provider
    // ResolvablePath is a relative path the provider can turn into a download
    // URL. It is required from a storageapi.Presigner and read from no other
    // provider: a store that serves no URLs says so by leaving the interface
    // out, so there is no under-declaring left for the suite to probe for.
    ResolvablePath string
    // Root is the directory a filesystem-backed provider keeps its objects in.
    // The suite plants symlinks and Windows junctions inside it that point out
    // of it, then requires every operation to refuse them. Links arrive in a
    // store from an operator's own "ln -s", a bind mount, an rsync'd tree or a
    // USB stick, and a provider that follows one reads and writes anywhere the
    // server process can.
    //
    // Root is also what tells the escaping-name cases where the store ends, so
    // they can require that a name pointing past it reached nothing.
    Root string
    // NoFilesystemRoot declares that the provider keeps its objects somewhere
    // the suite cannot plant a link, so the escape subtests do not apply and are
    // skipped. A provider declaring Browse and Write sets this or Root, never
    // both and never neither: an omission that silently skipped the security
    // cases would let a provider certify green with no confinement at all.
    NoFilesystemRoot bool
}
```

Subject is a provider instance plus what the suite needs to exercise it.
