`uiapi` lets a running module take a page of its own out of the sidebar, and
put it back. A module imports it when one of its features can be switched
off, such as a planner, which hides its Customers page while the customer
records are off.

The module names `ui.hide` in the `requires` list of its manifest and calls
`Hide` with every entry it hides now. An entry is written as the operator
writes one in `hidden_contributions`: `pages/customers` or
`file_action/plan`. Each call carries the whole list, and a call with none
shows every entry again.

The host keeps the list in memory while the process runs, and forgets it when
the process starts again. So a module calls `Hide` after each start, once it
knows what is switched off. It cannot hide another module's entries, and it
cannot show an entry the operator hid. A hidden page still opens from a
direct link. The rules are ADR-20261021-6h2.

## `uiapi` {#uiapi}

```go
import "github.com/prusa3d/prusa-connect/sdk/uiapi"
```

Package uiapi is how a module hides entries of its own browser half while it runs.

A module whose feature is switched off calls Hide, and the host takes the entries out of the listing the web app reads. An entry is a slot key, a slash and an identity, such as "pages/customers" or "file\_action/plan". Each call sends the whole list, and an empty list shows every entry again.

The host forgets the list when the instance stops, so call Hide again after a start. A module can hide only its own entries, and it cannot show an entry the operator hid.
