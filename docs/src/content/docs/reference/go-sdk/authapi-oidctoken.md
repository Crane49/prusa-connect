`oidctoken` reads the two things every OpenID Connect provider reads the same
way: a compact JWS, and the JWKS an issuer publishes its signing keys in. It
is the JOSE half only. Discovery, the authorize redirect, the token exchange
and the claim checks that bind a token to one login stay in the provider.
What binds a token depends on what asked for it.

A provider builds one `KeySet` per issuer with `NewKeySet` and keeps it for
the life of the instance. Nothing is fetched at construction, so an issuer
that is down does not stop the server from starting. `Verify` then checks a
token against a `Policy` in the order that costs least. The algorithm is
refused before any key is fetched, so a token claiming `alg none` never costs
the issuer a request. The payload is handed back only once the signature
holds. What the payload says is the caller's question, and `Audience` reads
the `aud` claim in both shapes the specification allows.

`Accepted` builds the policy's list from the algorithms an issuer lists in its
discovery document. It keeps the ones this package can check, and an HS
algorithm only when there is a client secret to check it with. A key set reads RSA, EC and
Ed25519 keys. `VerifyRS256` is `Verify` with RS256 alone.

A verifier maps each refusal onto the one [`authapi`](./authapi.md) declares.
The host tells a caller what to do from that: renew an expired token, point a
client at the right server, or wait for the issuer.

```go
package acmeoidc

import (
	"context"
	"encoding/json"
	"errors"
	"net/http"
	"slices"
	"time"

	"github.com/prusa3d/prusa-connect/sdk/authapi"
	"github.com/prusa3d/prusa-connect/sdk/authapi/oidctoken"
)

// claims is the part of an ID token this verifier reads.
type claims struct {
	Subject  string             `json:"sub"`
	Issuer   string             `json:"iss"`
	Audience oidctoken.Audience `json:"aud"`
	Expires  int64              `json:"exp"`
	Name     string             `json:"name"`
	Email    string             `json:"email"`
}

// verifier is the bearer half of an identity provider.
type verifier struct {
	keys     *oidctoken.KeySet
	issuer   string
	audience string
}

var _ authapi.TokenVerifier = (*verifier)(nil)

func newVerifier(jwksURL, issuer, audience string) *verifier {
	return &verifier{
		keys:     oidctoken.NewKeySet(jwksURL, http.DefaultClient, nil),
		issuer:   issuer,
		audience: audience,
	}
}

func (v *verifier) VerifyToken(ctx context.Context, token string) (authapi.Identity, error) {
	payload, err := oidctoken.VerifyRS256(ctx, token, v.keys)

	switch {
	case errors.Is(err, oidctoken.ErrMalformed):
		return authapi.Identity{}, authapi.ErrTokenMalformed
	case errors.Is(err, oidctoken.ErrKeysUnavailable):
		return authapi.Identity{}, authapi.ErrTokenKeys
	case err != nil:
		return authapi.Identity{}, authapi.ErrTokenSignature
	}

	var c claims
	if err = json.Unmarshal(payload, &c); err != nil {
		return authapi.Identity{}, authapi.ErrTokenMalformed
	}

	switch {
	case c.Issuer != v.issuer:
		return authapi.Identity{}, authapi.ErrTokenIssuer
	case !slices.Contains(c.Audience, v.audience):
		return authapi.Identity{}, authapi.ErrTokenAudience
	case time.Now().Unix() >= c.Expires:
		return authapi.Identity{}, authapi.ErrTokenExpired
	}

	return authapi.Identity{
		Subject:     c.Subject,
		Email:       c.Email,
		DisplayName: oidctoken.DisplayName(c.Name, c.Email, c.Subject),
		ExpiresAt:   c.Expires,
	}, nil
}
```

A key the issuer does not publish is answered from the cached set for
`MinKeyTTL`, 30 seconds, before the set is fetched again. A forged token
naming a random key is therefore one request at the issuer per window and not
one per token.

### `MinKeyTTL` {#authapi-oidctoken-minkeyttl}

```go
const MinKeyTTL = 30 * time.Second
```

MinKeyTTL is the floor under any max-age the issuer sends, and the window an unknown key waits before the issuer is asked again. It stops tokens that name unknown keys from turning into a flood of requests at the issuer.
