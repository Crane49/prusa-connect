`linkapi` is the contract a module implements so that this server can show it
on the links page. A link is this server's connection to the server above it
and to the servers that joined under it. The module makes the connection, and
this contract is how the host reads its state and sends an operator's decision
to it.

Use this package when your module connects this server to other servers, with
any protocol. The module's [manifest](./manifest.md) declares `kind: link`.
The module then answers the
methods below on the session it already runs with
[`wirerpc`](./wirerpc.md):

| method | direction | what it does |
|---|---|---|
| `link.status` | host to module | returns a `Status`, the whole state of the link |
| `link.approve` | host to module | admits one node below, by the id the status gave it |
| `link.revoke` | host to module | takes the admission away. The node stays in the status as `revoked` |
| `link.changed` | module to host | reports the whole status after a change |

A `Status` has this server's name and public key in the network, the `Uplink`
to the server above, every `Node` below with its `Admission`, and the
listeners the module opened.

A module implements the `Link` interface and installs `Handlers(link)`. It
reports a change with a `Reporter`. The host publishes the event
[`com.prusa.connect.link.state.changed`](../../event-types.md#com-prusa-connect-link-state-changed)
from that report, because a module cannot publish an event under the core's
namespace. The HTTP operations that reach these methods are
[`list-links`](../api/resources.md#list-links),
[`get-link`](../api/resources.md#get-link),
[`approve-link-node`](../api/resources.md#approve-link-node) and
[`revoke-link-node`](../api/resources.md#revoke-link-node).

```go
package tunnel

import (
	"context"
	"maps"
	"slices"
	"sync"

	"github.com/prusa3d/prusa-connect/sdk/linkapi"
	"github.com/prusa3d/prusa-connect/sdk/wirerpc"
)

// link keeps the reading the host asks for. The module's network code fills
// it in.
type link struct {
	mu      sync.Mutex
	reading linkapi.Status
	host    *linkapi.Reporter
}

// Status answers link.status.
func (l *link) Status(context.Context) (linkapi.Status, error) {
	l.mu.Lock()
	defer l.mu.Unlock()

	return l.copyOfReading(), nil
}

// Approve answers link.approve.
func (l *link) Approve(ctx context.Context, params linkapi.NodeParams) error {
	return l.decide(ctx, params.ID, linkapi.AdmissionAdmitted)
}

// Revoke answers link.revoke. The node stays in the reading as revoked.
func (l *link) Revoke(ctx context.Context, params linkapi.NodeParams) error {
	return l.decide(ctx, params.ID, linkapi.AdmissionRevoked)
}

func (l *link) decide(ctx context.Context, id linkapi.NodeID, to linkapi.Admission) error {
	l.mu.Lock()

	at := slices.IndexFunc(l.reading.Nodes, func(n linkapi.Node) bool { return n.ID == id })
	if at < 0 {
		l.mu.Unlock()

		return linkapi.ErrNoNode // crosses to the host as the same error
	}

	l.reading.Nodes[at].Admission = to
	reading := l.copyOfReading()
	l.mu.Unlock()

	// Tell the host, which publishes the event. A report that fails is not a
	// failed decision, because the host asks link.status again when it needs to.
	_ = l.host.Changed(ctx, linkapi.ChangedParams{Status: reading})

	return nil
}

func (l *link) copyOfReading() linkapi.Status {
	reading := l.reading
	reading.Nodes = slices.Clone(l.reading.Nodes)

	return reading
}

// serveLink adds the link methods to the ones the module already answers.
// conn is the session the host opened to this module.
func serveLink(conn *wirerpc.Conn, serves wirerpc.Methods) {
	maps.Copy(serves, linkapi.Handlers(&link{host: linkapi.NewReporter(conn)}))
}
```

The errors `ErrNoNode`, `ErrNotReady`, `ErrBusy` and `ErrInvalidReading`
cross the process boundary, so the host matches them with `errors.Is`. Any
other error reaches the host as one fixed sentence, and the detail stays in
the module's log. A `Status` is checked against the published limits, such as
`MaxNodes` and `MaxNodeIDBytes`, in the module before it is sent and in the
host after it arrives. `RoundTripMS` and `LastSeen` are pointers: leave one
nil when there is no measurement, because zero is a measurement.

This package connects nothing. It has no protocol, no keys and no network
code. The module under `packages/fractal` of this repository implements it for
Prusa Fractal, and the protocol packages start at
[`fractal`](./fractal.md). `Client` and `ChangedHandlers` are for the host,
and a module never builds them.

Package linkapi is the contract between the host and a link module. It defines the calls the host makes on the module, and the call the module makes on the host.

A link is the connection from this site to the sites above and below it. A site joins one site above it and accepts other sites under it, so the sites form a tree.

The host calls link.status, link.approve, link.reject and link.revoke. A module installs Handlers on its session and the host uses a Client.

The module calls link.changed with its new Status, and the host publishes the link state event from it. The host installs ChangedHandlers and the module uses a Reporter.
