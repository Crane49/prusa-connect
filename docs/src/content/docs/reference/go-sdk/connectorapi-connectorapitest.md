`connectorapitest` is the conformance suite a printer driver passes. It
proves the property the capability model rests on: whatever profile the host
hands a driver, the resolved set never carries a key the `Baseline` did not.
A driver that unions the profile in, or ignores it, fails here rather than in
a workshop.

`RunDriverContract` runs every case once per direction the driver implements.
For an outbound driver the `Subject` names an `Endpoint` and declares either
`Connectable` or `NoLoopback`. For an inbound one it names `Dial`, and the
suite mounts the routes on a loopback server of its own. Every subject
declares either `SafeVerb`, a verb with no physical effect that the suite
sends through `Do`, or `NoSafeVerb`. The declaration is required because the
halves those flags switch off are the whole ceiling assertion, and the suite
says which halves it skipped. `BaselineErrors` checks a baseline on its own,
without a session.

```go
package acmeshelf

import (
	"net"
	"testing"

	"github.com/prusa3d/prusa-connect/sdk/connectorapi"
	"github.com/prusa3d/prusa-connect/sdk/connectorapi/connectorapitest"
)

// startFakeShelf listens on a loopback port and answers as a shelf would. The
// protocol behind it is the driver's own test fixture.
func startFakeShelf(t *testing.T) string {
	t.Helper()

	listener, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		t.Fatal(err)
	}

	t.Cleanup(func() { _ = listener.Close() })

	return listener.Addr().String()
}

func TestContract(t *testing.T) {
	connectorapitest.RunDriverContract(t, func(t *testing.T) connectorapitest.Subject {
		return connectorapitest.Subject{
			Driver:      driver{},
			Endpoint:    connectorapi.Endpoint{Address: startFakeShelf(t)},
			Connectable: true,
			SafeVerb:    connectorapi.VerbSendInfo,
		}
	})
}
```

## `connectorapi/connectorapitest` {#connectorapi-connectorapitest}

```go
import "github.com/prusa3d/prusa-connect/sdk/connectorapi/connectorapitest"
```

Package connectorapitest is the conformance suite for connectorapi.Driver implementations. The drivers in this repository and a community author's drivers pass the same suite, or neither ships.

It proves the property the capability model rests on: a driver's resolved capability set never contains anything its Baseline did not, whatever the host handed it. A driver that unions its profile in, or that ignores the profile and reports its baseline unchanged, fails here rather than in the field.

Both directions run the same cases. The suite reads connectorapi.Directions and exercises the halves the driver implements: it dials an outbound driver at Subject.Endpoint, and it mounts an inbound driver's routes on a loopback server and has Subject.Dial make one device dial them. A dialled-in device reaches the same three tiers, the same descriptor rules and the same Do as a dialled-out one.

Call it from the driver's own \_test.go. An outbound subject names Endpoint and Connectable; an inbound one names Dial, and the suite owns the server:

	func TestContract(t *testing.T) {
	    connectorapitest.RunDriverContract(t, func(t *testing.T) connectorapitest.Subject {
	        return connectorapitest.Subject{
	            Driver:      mydriver.New(),
	            Endpoint:    ...,
	            Connectable: true,
	            SafeVerb:    "core.command.get_status",
	        }
	    })
	}

An outbound subject declares either Connectable or NoLoopback, never both and never neither, and every subject declares either SafeVerb or NoSafeVerb the same way. The declaration is required rather than inferred because the halves those flags gate are the whole intersective ceiling and the whole of C6: a subject that never wrote one would certify green on a run that asserted the baseline and nothing else. The suite says which halves it ran and what a skipped half did not demonstrate.

NoLoopback describes the outbound half alone. An inbound driver has no such answer available: Host stands its routes up with no hardware in reach.

### `ResolutionErrors` {#connectorapi-connectorapitest-resolutionerrors}

```go
func ResolutionErrors(baseline, resolved connectorapi.Set) []error
```

ResolutionErrors reports a resolved set that the baseline does not contain, or that breaks the descriptor rules in its own right.

This is an earlier design decision's intersective ceiling, stated as an assertion: whatever the host offered, the answer is bounded by the driver's own code. The merged set is also run through the descriptor rules, because a merge can subtract a key another key depends on and a set nothing checks is one where a tier that lies looks like a tier that is right.

### `DialDevice` {#connectorapi-connectorapitest-dialdevice}

```go
type DialDevice func(t *testing.T, baseURL string) error
```

DialDevice makes exactly one device dial the routes the suite mounted and identify itself, so that the driver admits it and announces a session.

baseURL carries the prefix the suite mounted the driver under, which is not the driver's own root: a device that reaches the handler only when the prefix is absent is a driver that hard-coded where it was mounted.

Returning an error fails the case. Anything the device holds open is the implementation's to close, through t.Cleanup.

### `Host` {#connectorapi-connectorapitest-host}

```go
type Host struct {
    // contains filtered or unexported fields
}
```

Host is a host fake for an inbound driver: it implements connectorapi.Arrivals the way a real host does, and records what a driver admitted and announced.

It exists because an inbound driver needs no hardware and no loopback to be exercised. Its routes are an http.Handler, so a test mounts them, has a device dial them, and holds the session that comes out. Declaring that a driver cannot be connected to in a unit test is an answer only an outbound driver has.

Every method is safe for concurrent use: a driver serving many devices calls Admit and Arrived from many request goroutines.

### `Subject` {#connectorapi-connectorapitest-subject}

```go
type Subject struct {
    // Driver is the implementation under test.
    Driver connectorapi.Driver
    // Endpoint reaches a device the suite may connect to. It is read only when
    // the driver is outbound and Connectable is true.
    Endpoint connectorapi.Endpoint
    // Connectable is whether Connect can succeed in this test environment,
    // against hardware or against a loopback the driver exposes for its own
    // tests. It describes the outbound half.
    Connectable bool
    // NoLoopback declares that this driver cannot be dialled in a unit test at
    // all, so the outbound resolution and session halves are skipped. Setting
    // it is a statement that the driver has not demonstrated it intersects: the
    // ceiling assertions, and every assertion about Do, State and Close, are
    // the halves it turns off. A driver that can stand up a loopback sets
    // Connectable instead.
    //
    // It describes the outbound half only. An inbound driver's routes are an
    // http.Handler that the suite mounts itself, so there is nothing it could
    // be unable to reach.
    NoLoopback bool
    // Dial makes one device dial an inbound driver's mounted routes. It is
    // required for a driver that implements connectorapi.Inbound and refused
    // for one that does not.
    Dial DialDevice
    // SafeVerb names a capability the suite may actually invoke against the
    // device: one with no physical effect, such as a status query. The suite
    // sends it through Do and requires a Result back, which is what stops a
    // driver certifying with a Do nothing ever called.
    SafeVerb connectorapi.Capability
    // SafeArgs are the arguments to send with SafeVerb. The suite validates
    // them against the resolved set first, so they must satisfy it.
    SafeArgs map[string]string
    // NoSafeVerb declares that every verb this driver offers moves the machine,
    // so there is none the suite may send. The Do round-trip is then skipped
    // and only the refusal cases run.
    NoSafeVerb bool
}
```

Subject is a driver instance plus what the suite needs to exercise it.
