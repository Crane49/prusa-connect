`accessapi` is the one question a module asks the authorization graph about
somebody other than itself: may this subject perform this action on this
object. A print queue imports it to ask, before it starts a job at night,
whether the person who submitted that job may still operate that printer.

A module acts for a person while that person's request is open. It does not
need this package then: it passes the person's principal on `device.command`,
and the graph answers for them. The question here is the one nothing else can
answer, because there is no open request to carry it.

The answer is one bit, so the call is bounded on two sides. The action is one
the instance's `permissions:` list names. The subject is one the host handed
the instance on `routes.serve` since the instance started. So a module cannot
ask about an action it did not declare, and it cannot ask about a person who
has never used it. That is what keeps a call answering one bit from reading the
whole graph one bit at a time.

A module whose install the operator approved with `check_absent_people` may
ask about any person the server holds, as a queue does after a restart. When the
server keeps local accounts, it answers false for a deleted person on every
path. Every such question counts against a burst of 600 and then 10 a second,
and past that the answer is `ErrTooManyQuestions`. Each question the bound lets
through is logged. See
[ADR-20260929-f4n](../../../../../decisions/20260929-f4n-a-module-may-ask-about-a-person-who-is-away.md).

A module whose install the operator approved with `list_people` may list the
people the server holds with `People`, as a planner does to assign a run to a
person. Each row is a subject, a name and a kind, sorted by name, and never an
e-mail address, a role or a grant. A server without local accounts answers an
empty list. A module without the approval reads `CodeMethodNotFound`. See
[ADR-20261021-x2b](../../../../../decisions/20261021-x2b-a-module-may-list-the-people.md).

## `accessapi` {#accessapi}

```go
import "github.com/prusa3d/prusa-connect/sdk/accessapi"
```

Package accessapi is how a module asks the host whether one principal may perform one action on one object.

A module that acts later than the request that asked for it, such as a print queue, calls Check before it acts.

The host refuses a question outside two bounds. The action must be in the instance's own permissions list. The subject must be the instance itself or one the host passed to it on routes.serve since it started. With the check\_absent\_people permission the subject may be any person of the server, user:\<id>. A link may also ask about a server it reported, node:\<id>.

An unknown object answers false, as an object the subject cannot reach. A deleted person answers false too.

With the list\_people permission a module may list the people with People.
