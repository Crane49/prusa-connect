A dashboard is a page of cards: a printer, a camera, a chart, a note. The
home page draws the default dashboard, and every dashboard has a link of its
own. The server keeps where each card sits on the grid and the card's
settings. It never reads the settings, because they belong to the card type
that draws them.

Who sees a dashboard is its visibility, held against the organization roles on
the `dashboard` resource kind. A viewer sees the dashboards visible to
everyone, an operator also those visible to operators, and an admin every one.
A dashboard the caller may not see answers `DASHBOARD_NOT_FOUND`, the same as
one that is not there, and the listing never counts it.

Making, changing and deleting a dashboard take an operator. A change sends the
whole dashboard with the revision it was read at, so two people editing one
wall do not write over each other. The later save is refused with
`DASHBOARD_CHANGED`, and the client reads the dashboard again. Choosing the
default takes an admin, and only a dashboard visible to everyone may be it.
Every change is published as `com.prusa.connect.dashboard.changed`, so a
screen drawing the dashboard reads it again.

## Operations {#operations}

### `create-dashboard` {#create-dashboard}

`POST /api/v1/dashboards`. Make a dashboard.

Writes one new dashboard with the cards the draft carries. A copy of a dashboard is made the same way. It takes operate_resource on the dashboard kind, and a visibility the caller would see.

- credential: bearer token. The client method is `createDashboard`
- request body: `application/json` (`DashboardDraft`), required
- response `201`: Created, `application/json` (`Dashboard`)
- errors: `401`, `403`, `404`, `409`, `422`, `500`, each a [problem document](../../error-codes.md)

### `delete-dashboard` {#delete-dashboard}

`DELETE /api/v1/dashboards/{dashboard}`. Delete a dashboard.

Removes the dashboard. Its id is never given out again. A deleted default leaves the home page drawing another dashboard. It takes operate_resource on the dashboard kind.

| parameter | in | type | required | description |
|---|---|---|---|---|
| `dashboard` | path | `string` | yes | The dashboard's id, as the listing answers it. |

- credential: bearer token. The client method is `deleteDashboard`
- request body: none
- response `204`: No Content, no body
- errors: `401`, `403`, `404`, `422`, `500`, each a [problem document](../../error-codes.md)

This operation has no sample: 204, for the same reason the resource delete is.

### `list-dashboards` {#list-dashboards}

`GET /api/v1/dashboards`. Every dashboard.

Every dashboard the caller sees, by name, and the one the home page draws. A dashboard visible to everyone takes view_resource on the dashboard kind, one visible to operators takes operate_resource, and one visible to admins takes configure_resource. The count never includes a dashboard the caller may not see.

- credential: bearer token. The client method is `listDashboards`
- request body: none
- response `200`: OK, `application/json` (`DashboardListing`)
- errors: `401`, `500`, each a [problem document](../../error-codes.md)

#### Sample {#sample-list-dashboards}

```sh
curl "http://127.0.0.1:8080/api/v1/dashboards" \
  -H "Authorization: Bearer $TOKEN"
```

```ts
await client.listDashboards();
```

### `replace-dashboard` {#replace-dashboard}

`PUT /api/v1/dashboards/{dashboard}`. Change a dashboard.

The draft carries the revision it was made against, and one made against an older revision is refused with DASHBOARD_CHANGED. It takes operate_resource on the dashboard kind, and a dashboard and a new visibility the caller sees.

| parameter | in | type | required | description |
|---|---|---|---|---|
| `dashboard` | path | `string` | yes | The dashboard's id, as the listing answers it. |

- credential: bearer token. The client method is `replaceDashboard`

### `set-default-dashboard` {#set-default-dashboard}

`PUT /api/v1/dashboards/default`. Choose the dashboard the home page draws.

Makes one dashboard the default, or none for a null id. Only a dashboard visible to everyone may be the default. It takes configure_resource on the dashboard kind.

- credential: bearer token. The client method is `setDefaultDashboard`
- request body: `application/json` (`DefaultDashboardBody`), required
- response `200`: OK, `application/json` (`SetDefaultDashboardOutputBody`)

#### Sample {#sample-set-default-dashboard}

```sh
curl -X PUT "http://127.0.0.1:8080/api/v1/dashboards/default" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
```
