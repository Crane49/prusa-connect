The event stream is one connection down which this server sends everything
that happens: a printer arriving, a job changing state, a resource failing,
a file transfer moving. A page or a module reads it instead of polling, and
the [event types](../../event-types.md) page lists every `type` it can
carry.

It is served as server-sent events, the browser's `EventSource` format, so a
plain `fetch` or the typed client reads it. The permission decision is taken
once, when the stream opens: everything the caller may `observe` is in, and
a grant withdrawn later narrows the stream without a reconnect. Events
published close together leave as one window and not one write each. Every
frame carries an `id`, its place in the log, and a client that reconnects
with `Last-Event-ID` resumes from there with no gap. Telemetry frames carry
no id. They are conflated, so there is nothing to replay.

## Which operation to call {#which-operation}

| you want to | call |
|---|---|
| follow the fleet live, or one printer, or one kind of event | [`stream-events`](#stream-events), narrowed with `origins` and `types` |
| count how many streams this server is serving | [`get-event-stream-stats`](#get-event-stream-stats) |

A stream ends on its own in two cases. A credential that expires or is
revoked closes it with a `prusa-connect.auth.expired` frame within 30
seconds. A reader that falls too far behind is sent
`com.prusa.connect.stream.continuity.lost` instead of part of a stream. On
that frame, reload state from the API before reading further.

## Operations {#operations}

### `get-event-stream-stats` {#get-event-stream-stats}

`GET /api/v1/events/stats`. How many readers the event stream has.

Counts the event streams this server is serving right now, over every reader. It is a process-wide number: it names no printer and no caller, and it is the same answer whatever the caller may see. Use it to tell a server nobody is watching from one under load before opening a stream of your own.

It counts connections rather than people. One browser with three tabs open is three, and a reader that has gone away is counted until this server notices the socket closed.

- credential: bearer token. The client method is `getEventStreamStats`
- request body: none
- response `200`: OK, `application/json` (`EventStreamStats`)
- errors: `401`, `500`, each a [problem document](../../error-codes.md)

#### Sample {#sample-get-event-stream-stats}

```sh
curl "http://127.0.0.1:8080/api/v1/events/stats" \
  -H "Authorization: Bearer $TOKEN"
```

```ts
await client.getEventStreamStats();
```

The server answers `200`:

```json
{
  "subscribers": 3
}
```

### `stream-events` {#stream-events}

`GET /api/v1/events`. Read the event stream.

Opens a server-sent event stream of everything the caller may observe. The authorization decision is taken once, here, and channel membership is the decision afterwards, so no event costs a permission check. A grant withdrawn while the stream is open narrows it without a reconnect and names each origin the reader lost in a com.prusa.connect.stream.origin.withdrawn frame, and a credential that stops being accepted, by revocation or by expiry, ends the stream with a prusa-connect.auth.expired frame within 30 seconds. Frames are coalesced into windows rather than forwarded one per event, and a reader that falls far enough behind is told so by a com.prusa.connect.stream.continuity.lost frame rather than quietly given part of a stream.

| parameter | in | type | required | description |
|---|---|---|---|---|
| `origins` | query | `array or null` | no | Narrow the stream to these origins, each as kind:id, comma separated. Omitted means every origin the caller may observe. An origin the caller may not observe refuses the whole request, and the refusal names none of them. |
| `types` | query | `array or null` | no | Narrow the stream to these event types, comma separated, each the envelope's own type such as com.prusa.connect.device.arrived. Omitted means every type this caller may see. A type this build never publishes is not refused: it matches nothing, so a client may name one a later release adds. This narrows what is sent and never what may be seen, which is what origins does. |
| `interval_ms` | query | `integer` | no | The coalescing window in milliseconds: everything published inside one leaves as one write. Omitted means the server's default. The floor is the shortest window the server allows. |
| `Last-Event-ID` | header | `string` | no | The id of the last frame this client saw, replayed by EventSource on its own. It is either one event's place, as epoch:kind/id:offset, or the whole cursor this server stamps on a window that moves it. |

- credential: bearer token. The client method is `streamEvents`
- request body: none
- response `200`: A server-sent event stream. Each frame carries the CloudEvents JSON envelope in its data field, the envelope's type in its event field, and the place to resume from in its id field. Telemetry frames carry no id: they are conflated rather than replayed, so there is no place in them to resume from, `text/event-stream` (`string`)
- errors: `401`, `403`, `422`, `429`, `500`, each a [problem document](../../error-codes.md)

#### Sample {#sample-stream-events}

```sh
curl "http://127.0.0.1:8080/api/v1/events" \
  -H "Authorization: Bearer $TOKEN"
```

```ts
await client.streamEvents();
```
