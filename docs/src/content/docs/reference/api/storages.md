A storage is a folder on this server's disk, declared as an instance of the
`storage` kind under [resources](./resources.md). A print file is uploaded
here first, then sent from here to a printer with `send-device-file` on the
[devices](./devices.md) page.

These paths are about a storage's contents. Its declaration, and whether it
is running, are on the resources page. A path is always relative to the
storage's root, and one carrying a `..` segment is refused. A storage's type
decides which file extensions it accepts and what it can do, and the listing
reports both so a client does not offer an operation that cannot work. An
upload is streamed to the storage and answered with the SHA-256 the storage
took of what it wrote. Reading takes `read_storage` and writing
`write_storage`, both on the storage kind.

## Which operation to call {#which-operation}

| you want to | call |
|---|---|
| see which storages are running and what each can do | [`list-storages`](#list-storages) |
| browse a folder, or describe one entry | [`list-storage-files`](#list-storage-files), [`stat-storage-entry`](#stat-storage-entry) |
| put a file in | [`upload-storage-object`](#upload-storage-object), or the same upload as a POST, [`post-storage-object`](#post-storage-object) |
| get a file back, resuming if interrupted | [`download-storage-object`](#download-storage-object) |
| make a folder, or move or rename an entry | [`create-storage-folder`](#create-storage-folder), [`move-storage-entry`](#move-storage-entry) |
| remove a file, or a folder and everything under it | [`delete-storage-entry`](#delete-storage-entry) |
| remove several files and folders in one request | [`delete-storage-entries`](#delete-storage-entries) |

`delete-storage-entry` on a folder removes everything under it in one call,
and nothing brings it back. An upload to a path that already holds a file
replaces it.

### `create-storage-folder` {#create-storage-folder}

`POST /api/v1/storages/{storage}/folders`. Make a folder in a storage.

Creates a folder and any parent it needs. It takes write_storage.

| parameter | in | type | required | description |
|---|---|---|---|---|
| `storage` | path | `string` | yes | The name the storage is declared under. |

- credential: bearer token. The client method is `createStorageFolder`

- response `200`: OK, `application/json` (`StoragePathBodyBody`)
- errors: `400`, `403`, `404`, `409`, `413`, `415`, `422`, `500`, each a [problem document](../../error-codes.md)

#### Sample {#sample-create-storage-folder}

```sh
curl -X POST "http://127.0.0.1:8080/api/v1/storages/local/folders" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "path": "models/spares"
  }'
```

```ts
  body: {
    path: "models/spares",
  },
});
```

The server answers `200`:

```json

  "path": "models/spares"
}
```

### `delete-storage-entries` {#delete-storage-entries}

`POST /api/v1/storages/{storage}/deletions`. Remove several entries from a storage.

Deletes every file and folder the list names, a folder with everything under it. Every path is checked first, and a list holding a path with a .. segment or naming the storage root removes nothing. The deletes are not one atomic step: every entry is tried, the ones removed stay removed, and when any entry is still there the answer is core.storage/DELETE_INCOMPLETE, so list the folder and send what remains. It takes write_storage.

### `download-storage-object` {#download-storage-object}

`GET /api/v1/storages/{storage}/content`. Download a file from a storage.

Serves the file's bytes, with a length and a modification time, and answers a Range request so an interrupted download resumes. A storage whose download_url is true serves the file itself: the answer is a 307 redirect to a URL that storage handed out, and a client follows it to read the bytes. It takes read_storage.

### `get-storage-thumbnail` {#get-storage-thumbnail}

`GET /api/v1/storages/{storage}/thumbnail`. The picture stored inside one file.

Serves the thumbnail the slicer wrote into a .gcode, .bgcode or .3mf file, as image/png or image/jpeg. It carries Last-Modified and an ETag taken from the storage's digest of the file, and a client that sends either back is answered 304 with no body while its copy is current. Cache-Control is private, no-cache, so a shared proxy never holds one caller's picture, and a browser shared by several people asks before every use, which checks read_storage for the person asking. A file that carries no picture answers 404 with core.storage/NO_THUMBNAIL. It takes read_storage, the same permission as reading the file, because the picture is part of the file.

| parameter | in | type | required | description |
|---|---|---|---|---|
| `storage` | path | `string` | yes | The name the storage is declared under. |
| `path` | query | `string` | yes | The file, relative to the storage root. |
| `If-None-Match` | header | `string` | no | The entity tag of the picture this client already has. A picture with the same tag answers 304 with no body. |
| `If-Modified-Since` | header | `string` | no | The Last-Modified of the picture this client already has. A file no newer than it answers 304 with no body. |

- credential: bearer token. The client method is `getStorageThumbnail`
- request body: none
- response `200`: The picture stored inside the file, `image/jpeg` (`binary`) or `image/png` (`binary`)
- errors: `304`, `400`, `403`, `404`, `409`, `413`, `415`, `422`, `500`, each a [problem document](../../error-codes.md)

This operation has no sample: one PNG or JPEG picture, for the same reason the camera's still image is.

### `post-storage-object` {#post-storage-object}

`POST /api/v1/storages/{storage}/content`. Upload a file into a storage, as a POST.

Writes the request body into the storage at the given path, creating parent directories and replacing any file already there. The storage's type decides what extensions it accepts. The file is streamed: nothing here holds it. The answer carries the SHA-256 the storage took of the bytes it wrote, so a client that hashed what it sent can check the two agree. The same upload is published under PUT and under POST. It takes write_storage.

| parameter | in | type | required | description |
|---|---|---|---|---|
| `storage` | path | `string` | yes | The name the storage is declared under. |
| `path` | query | `string` | yes | The entry, relative to the storage root. |
| `temporary` | query | `boolean` | no | Write the file as a temporary copy: a file on its way to a printer that is not kept. The server puts it in a folder of its own and answers where, and only the last part of path, the file's name, is used. A file uploaded without it is never deleted by the server. |

- credential: bearer token. The client method is `postStorageObject`
- request body: `application/octet-stream` (`binary`), required
- response `200`: OK, `application/json` (`SavedObjectBodyBody`)
- errors: `400`, `403`, `404`, `409`, `413`, `415`, `422`, `500`, each a [problem document](../../error-codes.md)
