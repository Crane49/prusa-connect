Printers on one network find each other with mDNS, which is DNS sent to
every machine on the same network. Each server announces its API port, and
it listens for the announcements of the others. These paths read the list of
printers it hears, and switch whether it announces itself.

A printer on the list is a name and an address. Being on it grants that
printer nothing. The list holds at most 256 printers, and a printer leaves it
when its record expires or when it sends a goodbye. A server does not list
itself.

A hidden server announces nothing, so the others drop it from their lists.
It still lists the printers it hears. It still serves its page and its API at
its address, and the login still protects them. The setting is stored in the
machine-owned file and applies at once. `core.discovery.hidden` in the
configuration file sets the value a server starts with, and a stored choice
wins over it. `core.discovery.enabled: false` switches the announcer and the
list off together.

This server can also answer the time on UDP port 123, for a camera or
another device on a network with no internet. It is off by default. The
switch is stored in the machine-owned file and applies at once, and
`core.time_server.enabled` sets the value a server starts with. When the port
does not open, the state is `failed` and the reason says why
([ADR-20261112-4ds](../../../../../decisions/20261112-4ds-the-core-can-serve-the-time-on-the-local-network.md)).

Reading takes `view_resource` on the link kind, which every org viewer
holds. Changing the setting takes `configure_resource` on the same kind,
which every org administrator holds.

### `get-discovery-visibility` {#get-discovery-visibility}

Reports the hidden setting and what the announcer is doing. It takes view_resource on the link resource kind, which every org viewer holds.

- credential: bearer token. The client method is `getDiscoveryVisibility`
- request body: none
- response `200`: OK, `application/json` (`Visibility`)

### `list-nearby-printers` {#list-nearby-printers}

`GET /api/v1/discovery/nearby`. The printers this server hears on the local network.

Every printer or server that announces itself over mDNS on the same network, with the address of its own web page. A printer on this list is a name and an address, and being on it grants nothing. The list holds at most 256 entries, and an entry leaves it when its record expires or its printer sends a goodbye. An entry whose address is the one a printer connected to this server comes from names that printer in device_id, when the caller holds observe on it. A printer that is away is named by the address it last came from, until a connected printer comes from that address. It takes view_resource on the link resource kind, which every org viewer holds.

- credential: bearer token. The client method is `listNearbyPrinters`
- request body: none
- response `200`: OK, `application/json` (`NearbyOutputBody`)
- errors: `401`, `403`, `500`, each a [problem document](../../error-codes.md)

```sh
curl "http://127.0.0.1:8080/api/v1/discovery/nearby" \
```

### `set-discovery-visibility` {#set-discovery-visibility}

`PUT /api/v1/discovery/visibility`. Hide this server from the local network, or show it again.

Stores the hidden setting in the machine-owned file and applies it at once, with no restart. A hidden server announces nothing and sends a goodbye for every record it announced, so the other printers drop it from their lists. It still serves its page and its API at its address. The stored value wins over core.discovery.hidden in the configuration file. It takes configure_resource on the link resource kind, which every org administrator holds.

- credential: bearer token. The client method is `setDiscoveryVisibility`
- request body: `application/json` (`VisibilityBody`), required
- response `200`: OK, `application/json` (`Visibility`)
- errors: `401`, `403`, `404`, `422`, `500`, each a [problem document](../../error-codes.md)

#### Sample {#sample-set-discovery-visibility}

```sh
curl -X PUT "http://127.0.0.1:8080/api/v1/discovery/visibility" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "hidden": true
  }'
```

```ts
await client.setDiscoveryVisibility({

    hidden: true,

});
```

### `set-time-server` {#set-time-server}

`PUT /api/v1/time-server`. Start or stop answering the time on the local network.

Stores the time server switch in the machine-owned file and applies it at once, with no restart. While on, this server answers SNTP requests on UDP port 123 with this machine's clock, for devices on a network with no internet. A machine that will not open the port leaves the switch on and reports the state failed with the reason. The stored value wins over core.time_server.enabled in the configuration file. It takes configure_resource on the link resource kind, which every org administrator holds.

- credential: bearer token. The client method is `setTimeServer`
- request body: `application/json` (`SetTimeServerInputBody`), required
- response `200`: OK, `application/json` (`TimeServerState`)
- errors: `401`, `403`, `404`, `422`, `500`, each a [problem document](../../error-codes.md)

#### Sample {#sample-set-time-server}

```sh
curl -X PUT "http://127.0.0.1:8080/api/v1/time-server" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true
  }'
```

