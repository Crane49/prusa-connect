Generated by 'make generate-device-models' from the model catalogue this build links. Do not edit: change the table in Go and regenerate.

A device record carries the machine's own spelling in `model` and nothing else. `CoreOneL_INDX` is a firmware string, and a person reading a fleet screen wants the name the machine is sold under and a picture of it. This set is the join between the two.

The key is the machine's own spelling. It is what a device reports, what the `model` member of a device record carries, and what the listing's model filter takes, so a client joins a device row onto a row here without a second table.

The icon key names a family and not a model. Machines in one family look alike, so a page ships a handful of drawings and maps several models onto one. Read it as an open value: a newer core may name a key a page has no drawing for, and the answer to that is a generic device.

It is the set this build carries and not a catalogue of everything Prusa makes. A machine reporting a model no row names still connects and is still listed: it runs on its driver's baseline instead of a capability profile.

## Vocabulary version

This build carries `device-models` version `2.0.0`, in format `1.2`. The content version moves when a model is added, retired or redefined; the format version moves when the shape of a row changes. A row leaves the set the way every published entry leaves one: it is marked deprecated in one release and removed in a later one. Before the server's 1.0.0 release, a major version of the set may drop a row without the deprecation.

## Reading the set from a running server

`GET /api/v1/vocabularies/device-models` answers with what **this build** carries, from the same catalogue this page is generated from. It takes no credential.

That answer also carries what this page cannot know, because it depends on the modules a binary was built with:

- a row for each machine a driver in the build declares, with its drawing when the driver has one
- each dialect the rows are reached through, and what it needs from a person before a machine can arrive
- each declared model the server refused, and why
