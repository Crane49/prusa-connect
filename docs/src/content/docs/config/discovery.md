The server announces itself on the local network over mDNS, the way a printer
does, so PrusaSlicer and the printers find it without an address typed in. It
listens there too, and lists the printers it hears on a printer's page.

`core.discovery.enabled` turns both off. `core.discovery.hidden` makes the
server announce nothing, so neither PrusaSlicer nor anything else finds it on
the network, while it still hears the printers. The switch in the web app's
settings wins over this key once a person uses it.

On macOS, an app needs Local Network permission to reach other machines. A
server started from an app without it sends nothing over mDNS. The log then
warns once, and the web app's network settings say the announcement failed.
Allow the app under System Settings, Privacy & Security, Local Network. Then
start the app and the server again.

## What the record says {#what-the-record-says}

Every service name the server announces carries the same short list of
keys in its TXT record. A TXT record is the part of an mDNS answer that
holds `key=value` pairs. Every machine on the network can read it, so it
never holds a token, a password or an account name.

| key | value |
|---|---|
| `path` | `/`, where the API starts |
| `version` | the build the server runs |
| `api` | `v1` |
| `tls` | `1` when the API port expects https, and absent when it does not |
| `id` | the id of this server, the same value as `instance_id` in `GET /api/v1/health` |

The id is random and the server writes it once, on the first start. It
stays the same when the server gets a new address, so a client that saw the
server at one address knows it again at another one. A copy of the database
carries the id with it: a server restored from a backup answers to the old
id.

Keep `core.discovery.services` at its default unless a guide tells you
otherwise.

## When the system already answers for the host name {#system-host}

The server answers for `<hostname>.local` itself, with the addresses of the
machine. Many machines already run another mDNS responder that answers for
that name: Avahi on Raspberry Pi OS and most desktop Linux systems, and
mDNSResponder on macOS. When the two announce different addresses for the
name, they disagree about who holds it, and one of them renames the machine
to `<hostname>-2.local`.

Set `core.discovery.host_records: system` on such a machine. The server then
announces only its services, and the other responder answers for the
addresses. The startup line says `host_records=system`.

Each service names the host the other responder holds. The server asks that
responder for the name of its own address, so it follows a rename such as
`<hostname>-2.local`. Until the answer comes, it names the host the
operating system reports. The other responder therefore has to answer for
the reverse name of each address. Avahi does with its default
`publish-addresses=yes`, and mDNSResponder does too.

Set `system` only where such a responder runs. Without one, nothing answers
for the host the services name. PrusaSlicer then finds the server but cannot
reach it. `avahi-resolve -n <hostname>.local` on the machine shows whether a
responder answers.

### core

Every key has a working default, so a file with no `core:` block starts a server. A key this build does not read is refused at startup, with the line it is written on.

| key | type | default | required | what it does |
|---|---|---|---|---|
| <a id="key-core-discovery-enabled"></a>`core.discovery.enabled` | true or false | `true` | no | Announce this server on the local network over mDNS, and list the other printers it hears there. |
| <a id="key-core-discovery-services"></a>`core.discovery.services` | list of text | `_prusalink._tcp` and `_prusa-connect._tcp` | no | The mDNS service names this server announces itself under, one record for each. |
| <a id="key-core-discovery-hidden"></a>`core.discovery.hidden` | true or false | `false` | no | Start hidden: the server announces nothing, so PrusaSlicer does not find it, and still hears the printers. The web app's switch wins once a person uses it. |
| <a id="key-core-discovery-host-records"></a>`core.discovery.host_records` | text | `own` | no | Who answers for this machine's host name: own, this server, or system, another mDNS responder on this machine such as Avahi. With system the server announces only its services. |
