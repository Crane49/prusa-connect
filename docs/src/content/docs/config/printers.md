By default printers dial the same address as the web app. A connector, the
code that speaks to one kind of printer, can listen on a port of its own
instead, which is what an encrypted printer connection needs. That listener is
written under `core.connectors.<name>.config.listener`, with `addr`, `tls` and
`handshake_timeout`. The setup wizard writes it when it encrypts either
connection. See [Encryption](encryption.md).

`core.frontend.printer_address` is the address the page that adds a printer
writes into `prusa_printer_settings.ini`. Set it when printers reach the server
by another name than browsers do. See
[Printer configuration](../printer-configuration.md).

The `core.device_*` keys bound what the server keeps for the printers, in
memory and on disk. That is the state each one reports, and the folder
listings and the pictures of their files. The state budget is for one printer. The caches
are shared by all of them. `core.preview_cache_bytes` bounds the preview
pictures from print files that the server keeps in memory.

### core

Every key has a working default, so a file with no `core:` block starts a server. A key this build does not read is refused at startup, with the line it is written on.

| key | type | default | required | what it does |
|---|---|---|---|---|
| <a id="key-core-frontend-printer-address"></a>`core.frontend.printer_address` | text | - | no | The origin printers dial, such as http://192.168.1.50:8080, written into the add-printer page's settings file. Not a loopback name. Empty uses the page's own address. |
| <a id="key-core-connectors-name-type"></a>`core.connectors.<name>.type` | text | - | when the instance is written | The printer driver this instance runs, for example xbuddy. |
| <a id="key-core-connectors-name-enabled"></a>`core.connectors.<name>.enabled` | true or false | `true` | no | Start this instance. An instance with no enabled key is started. |
| <a id="key-core-connectors-name-config"></a>`core.connectors.<name>.config` | mapping | - | no | The settings of the driver. The core passes the block to the driver and does not read it. |
| <a id="key-core-device-state-budget"></a>`core.device_state_budget` | number | `262144` | no | How many bytes of reported state the server keeps for one device. At the limit the server refuses a new state path and still updates the paths it has. |
| <a id="key-core-preview-cache-bytes"></a>`core.preview_cache_bytes` | number | `33554432` | no | How many bytes of preview pictures from print files the server keeps in memory. The printer build defaults to 1048576. |
