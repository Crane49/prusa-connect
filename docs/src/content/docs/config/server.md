These keys bound how the server uses the machine and name it among other
servers. The defaults suit almost everybody, and the setup wizard asks them on
its advanced path only.

`core.site` is this server's name in every event it sends. Give each server
its own when you connect several of them. `core.memory_limit` is the most
memory the server tries to use, for a small computer that runs other things
too. `core.overlay` names the file the web app saves the resources it
declares into. The setup wizard never offers it, because the wizard writes
beside it.

### core

Every key has a working default, so a file with no `core:` block starts a server. A key this build does not read is refused at startup, with the line it is written on.

| key | type | default | required | what it does |
|---|---|---|---|---|
| <a id="key-core-diagnostics-enabled"></a>`core.diagnostics.enabled` | true or false | - | no | Serve the diagnostics bundle an org admin downloads from Settings. Off, `make build` leaves it out. The minimal build never carries it. With no sign-in, off unless true. |
| <a id="key-core-diagnostics-send-url"></a>`core.diagnostics.send_url` | text | `https://beta.prusa3d.com` | no | The portal Settings sends the diagnostics bundle to. The browser uploads it, never the server. Empty hides Send to Prusa. |
| <a id="key-core-overlay"></a>`core.overlay` | text | `config.d/resources.json` beside your file | no | The file where the resource API saves the resources it declares. The server never changes your configuration file. |
| <a id="key-core-site"></a>`core.site` | text | `local` | no | This node's name in every event this server publishes. Give each node of a federation its own. |
| <a id="key-core-memory-limit"></a>`core.memory_limit` | number | - | no | The soft memory limit of the Go runtime, in bytes. When it is not set, Go reads GOMEMLIMIT. The server logs the limit at start when it sets one. |
| <a id="key-core-shutdown-timeout"></a>`core.shutdown_timeout` | duration | `15s` | no | How long a shutdown waits for open requests to end, and then how long it waits for the resources to stop. |
