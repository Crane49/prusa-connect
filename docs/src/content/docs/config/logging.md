The server writes its log to standard error: the window it runs in, or
`docker logs` and `journalctl`. `core.log.level` sets how much it writes: use
`debug` while you look for a problem, and `info` the rest of the time.
`core.log.format` writes `json` for a log collector. See
[Logging](../logging.md).

`core.observability.enabled` serves numbers about the server at `/metrics`,
for Prometheus and Grafana. Off, that address answers 404.
`core.observability.addr` serves them on a port of their own, which asks for no
sign-in, so keep that port off the public network. See [Metrics](../metrics.md).

### core

Every key has a working default, so a file with no `core:` block starts a server. A key this build does not read is refused at startup, with the line it is written on.

| key | type | default | required | what it does |
|---|---|---|---|---|
| <a id="key-core-log-level"></a>`core.log.level` | text | `info` | no | How much the process writes to its log: debug, info, warn or error. |
| <a id="key-core-log-format"></a>`core.log.format` | text | `text` | no | How one log line is written: text or json. |
| <a id="key-core-observability-enabled"></a>`core.observability.enabled` | true or false | `false` | no | Serve the metrics at /metrics. Off, the server answers 404 there. A binary built without the Prometheus client refuses true. |
| <a id="key-core-observability-addr"></a>`core.observability.addr` | text | empty, so the metrics stay on the API port, where a scrape signs in | no | Serve the metrics on a port of their own, written as host:port. That port asks for no credential, so publish it to your collector and to nothing else. |
